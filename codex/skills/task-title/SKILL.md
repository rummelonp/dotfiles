# タスク名

独自定義がない場合、タスク名は `<絵文字> <本体>` の形式にする。
デスクトップアプリでは `set_thread_title` を使う。
タイトルをプログラムから変更できない環境では適用せず、代わりの名前を本文へ出力しない。

## 種別

プロジェクトの `AGENTS.md` が独自の種別を定義していれば、そちらを優先する。
独自の完成書式がなければ、種別名全体を使って `<種別>: <本体>` の形式にする。
定義がなければ、以下を使う。

- **👑 統括**：長寿命で、判断と指揮だけを担い実装しない。
  起動時に領域名で付け、issue 番号は入れない。
  例：`👑 統括: 決済基盤`
- **#️⃣ issue 作業**：issue に紐づく起票、調査、実装。
  issue 番号が決まった時点で付ける。
  例：`#️⃣ 1234: ログイン失敗時の表示を直す`
- **🧩 単発**：issue に紐づかない調査、相談、実装。
  起動時の既定とし、issue を作らないと決めた時点で確定する。
  例：`🧩 CI の実行時間を調べる`

## 本体

本体の概要は作業内容を 20 字前後で書く。
issue タイトルや最初のプロンプトをそのまま写す必要はない。
サイドバーで末尾が切れず、他のタスクと区別できる名前にする。

## 改名

issue 番号が決まった時点で 🧩 から #️⃣ へ改名する。
作業の実態に合う名前が分かった時点で改名してよく、回数の制限はない。
タスク名はメッセージ送信の識別子ではないため、改名しても他タスクからの連絡経路は壊れない。
状態は「（吸収済み）」「（破棄）」のように、アーカイブでは伝わらない終わり方だけを末尾の括弧に書く。
