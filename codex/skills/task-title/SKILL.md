# タスク名

独自の定義がない場合、タスク名は `<絵文字> <本体>` の形式とする。
デスクトップアプリでは `set_thread_title` を使用する。
タイトルをプログラムから変更できない環境では本スキルを適用せず、本文中に代替のタスク名を出力しない。

## 種別

プロジェクトの `AGENTS.md` に独自の種別定義があれば優先する。
個別の書式指定がなければ、種別名全体を用いて `<種別>: <本体>` の形式とする。
独自の定義がない場合は以下を使用する。

- **👑 統括**: 長寿命で、判断と指揮のみを担い実装は行わない。起動時に領域名で設定し、issue 番号は含めない（例: `👑 統括: 決済基盤`）。
- **#️⃣ issue 作業**: issue に紐づく起票・調査・実装。issue 番号が確定した時点で設定する（例: `#️⃣ 1234: ログイン失敗時の表示を直す`）。
- **🧩 単発**: issue に紐づかない調査・相談・実装。起動時の既定とし、issue を作成しないと決まった時点で確定する（例: `🧩 CI の実行時間を調べる`）。

## 本体

作業内容の概要を 20 字前後で書く。
issue のタイトルや最初のプロンプトをそのまま転記する必要はない。
サイドバーで末尾が切れず、他のタスクと明確に区別できる名称にする。

## 改名

- issue 番号が決まった時点で 🧩 から #️⃣ へ改名する。
- 作業の実態に合った名称が判明した時点で随時改名してよい（改名回数の制限なし）。
- タスク名はメッセージ送信用のアドレスではないため、改名しても他タスクとの連絡経路には影響しない。
- 状態は「（吸収済み）」「（破棄）」のように、アーカイブだけでは伝わらない終了理由のみを末尾の括弧に記載する。
