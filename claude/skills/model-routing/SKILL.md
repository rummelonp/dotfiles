# サブエージェントのモデル選択

サブエージェントを起動する前に役割を選び、その役割に割り当てたモデルと起動設定で起動する。
役割と選択の原則は Claude Code、Codex、Antigravity で共通とし、割り当てと例外だけをエージェントごとに定める。
エージェントごとの例外は、選択の原則より優先する。

## 役割

| 役割 | 担当 |
|---|---|
| 調査 | 探索、調査、fan-out。ファイルを編集しない |
| 実装 | 機械的な修正、通常の実装、執筆の起草・書き換え |
| 上位実装 | `risk-based-review` の高リスク以上の実装、複数パッケージにまたがる実装、難度の高い実装・原稿、「実装」が複数回失敗したタスク |
| 設計・分析 | 設計判断（高リスク変更の事前検討を含む）、構成の検討、難度の高い原因分析（複数回の失敗、原因の特定不能など）。大量生成や定型作業には使わない |
| 標準レビュー | レビュー、bias-free 評価、指摘だけを返す推敲（原稿を書き換える推敲は起草と同じ扱い） |
| 高強度レビュー | 高リスク以上の変更のレビュー、上位の段が作った成果物のレビュー |

## 選択の原則

- 「段」は割り当てたモデルの価格の段を指し、上の表の役割の並びではない。同じモデルを割り当てた役割は同じ段とする。
- セッション自身のモデルは選択に影響させない。
- 通常リスクでは、正しさは実装者の格上げではなくレビュー強度で担保する。設計・分析を上位の段に任せても、実装の役割は上の表で選び直す。
- 迷ったら安価な段から試し、品質が足りなければ一段上げる。上の段がない、または起動に失敗した場合は元の段のまま続ける。
- レビューの段は、`risk-based-review` で決めた強度に対応する役割と、作成側の一段上のうち高い方にする。同じ段のレビューは、作成時の誤った前提を引き継ぎやすい。
- 作成側に一段上の段がない場合は、同じ段の新規サブエージェントに依頼し、コンテキストを分けて独立性を保つ。高リスク以上では、一段上げられない代わりに観点 A / B の 2 本に分けて依頼する（観点の定義は `risk-based-review`）。
- 委譲時は、作成に使った役割とモデルを記録する（記録先は plan ファイルやコミット trailer など、リポジトリの慣習に従う）。レビューの段を決めるときに必要になる。

## 割り当て（Claude Code）

段は `~/.claude/agents/*.md` の `model` で決まり、この skill にはモデル名を書かない（モデルと effort はエージェント定義だけで管理する）。
段の上下は各定義の `model` の価格順で決まる。現在の定義では `explorer` と `implementer` が安価な段、それ以外が上の段になる。

| 役割 | エージェント |
|---|---|
| 調査 | `explorer` |
| 実装 | `implementer` |
| 上位実装 | `senior_implementer` |
| 設計・分析 | `architect` |
| 標準レビュー | `reviewer` |
| 高強度レビュー | `reviewer` |

- Agent ツールの `subagent_type` に役割のエージェント名を指定する。これがモデルの指定に当たるので、`model` は渡さない（呼び出し時の `model` は定義より優先され、定義と食い違っても気づけない）。
- 組み込みの `Explore`、`Plan`、`general-purpose` は使わない（下記の代替時を除く）。どれもセッションのモデルを継承し、役割と関係なくモデルが決まる。
- 高強度レビュー専用の定義はない。上の段が作った成果物や高リスク以上の変更は、選択の原則の「作成側に一段上の段がない場合」に従い、新規の `reviewer` に依頼する。
- 役割のエージェントが現在のエージェント一覧にない場合は `general-purpose` で代替する（定義はセッション開始時に読み込まれるため、`~/.claude/agents/` に置いた直後もこれに当たる）。
  - `~/.claude/agents/<name>.md` があれば、その `model` を Agent ツールの `model` に明示し、本文の制約を依頼文に含める。
  - 定義ファイルもなければ、モデルはセッションの値を継承し、強度は新規コンテキストと観点の特化で担保する。
  - effort は Agent ツールで渡せないため、どちらの場合もセッションの値を継承する。
