# セッション名

セッション名は `<絵文字> <本体>` の形式とする。
デスクトップアプリでは `set_session_title`、CLI では `/rename <name>` を使用する。
- `set_session_title` には `session_id` の指定が必須である。自身の ID は `get_session` に `"self"` を渡して取得する（scratchpad パスに含まれる UUID は別物であり、渡しても `not found` となる）。
- いずれの手段も利用できない環境では本スキルを適用しない（代替の命名や報告は不要）。

## 種別

プロジェクトの `CLAUDE.md` に独自の種別定義があれば優先し、未定義なら以下を使用する。

- **👑 統括**: 長寿命で、判断と指揮のみを担い実装は行わない。起動時に領域名で設定し、issue 番号は含めない（例: `👑 統括: 決済基盤`）。
- **#️⃣ issue 作業**: issue に紐づく起票・調査・実装。issue 番号が確定した時点で設定する（例: `#️⃣ 1234: ログイン失敗時のエラー表示を直す`）。
- **🧩 単発**: issue に紐づかない調査・相談・実装。起動時の既定とし、issue を作成しないと決まった時点で確定する（例: `🧩 CI の実行時間を調べる`）。

## 本体

作業内容の概要を 20 字前後で書く。
issue のタイトルをそのまま転記する必要はなく、サイドバーで末尾が切れない長さに収める。

## 改名

- issue 番号が決まった時点で 🧩 から #️⃣ へ改名する。
- より適切な名称が判明した時点で随時改名してよい（改名回数の制限なし）。
- セッション名は `SendMessage` の宛先ではないため、改名しても他セッションとの連絡経路には影響しない。
- 状態は「（吸収済み）」「（破棄）」のように、アーカイブだけでは伝わらない終了理由のみを末尾の括弧に記載する。
