# 再レビューの範囲、記録したハッシュの書き直し、fixup コミットを畳む時期

`parallel-lanes` skill の 4 の 2 で、レビューを立てた後で、差し戻すときと、レーンの履歴を書き換える（4 の 3 の rebase、fixup の畳み込み）ときに読む。
節の番号（0〜7）は SKILL.md の節を指す。

この文書の「記録の最後のハッシュ」は、その項目のレビュアーに渡した先端のハッシュのうち、最後に書いたもの（書き直した後のものを含む）を指す（同じ欄に、ほかの項目のハッシュや取り込んだコミットも並ぶため）。

- レビューを立てた後で 4 の 3 の rebase や fixup の畳み込みで履歴を書き換えたら、記録の最後のハッシュを、書き換えた後の履歴でその先端に当たるコミットのものに書き直す（`git range-diff` で対応を取る）。
  書き換える前のハッシュは今の先端の祖先でなくなり、そこから範囲を取るとレーンの変更全体と基準ブランチの変更が混ざるためである。
- 差し戻したときは、記録の最後のハッシュから今の先端までを、`risk-based-review` skill の再レビューとして頼む。
  レビューの後で差し戻す前に統括が直したコミットもこの範囲に入るので、前回の指摘一覧に自己発見の修正として加える。
- 差し戻したレーンが fixup コミットを積んで返したら、上の再レビューは畳む前に立てる（畳むと修正分が畳み先のコミットに入り、記録の最後のハッシュからの範囲で修正分だけを切り出せなくなるため）。
  再レビューの上限が 0 回の分類など、再レビューを立てない場合は、`risk-based-review` skill のとおり修正を確かめてから畳む。
- レーンが残した fixup コミットは、再レビューを立てた場合はそれが通ってから、統括が `tidy-commits` skill で畳む。
  記録の最後のハッシュが畳んだ fixup コミットを指していれば、range-diff では対応が取れないので、畳んだ後の先端に書き直す（畳む前の先端と tree が同じことを `git diff` で確かめる）。
