# PR で取り込む repo

`parallel-lanes` skill を PR で取り込む repo で使うときに読む。
節の番号（0〜7）は SKILL.md の節を指す。各見出しの手順は、SKILL.md の同じ番号の節の中で行う。

## 0. 始める

- 基準ブランチを `pr-workflow` skill の base の決め方で決める。開いた PR の base を使う段は飛ばす（統括がいるブランチ自身の PR の base を引いてしまうため）。
- 作業ツリーが clean で、統括がメインの worktree で基準ブランチにいることを確かめてから、fetch して、リモートの基準ブランチを fast-forward で取り込む（古い先端から後続の項目を起動しないため）。

## 4. 受け入れる

4 の 3 と 10 を除いた手順をレーンの worktree で行い、通ったら push して PR を作る。
PR を作った時点で受け入れを終えたものとする（CI が回す検証が宣言されていれば、下の CI の結果を確かめるか、終わっていないことを記録の「受け入れ結果」に書いた時点で）。
3 の数え方でマージ待ちに移して、1 に戻って次の候補を引く（5 の「取り込んだ後」は PR がマージされた後に行う）。

- PR は、0 の開始時に得た承認の範囲で、`pr-workflow` skill に従って作る。base には、基準ブランチを呼び出し元の指定として渡す。
- issue の項目では、PR 本文に `Closes #<n>` を入れる（マージで issue が閉じる。閉じない場合は 5 で閉じる）。
- CI が回す検証が宣言されていれば、`gh pr checks`（読むだけ）の結果も確かめる。落ちていれば 4 の 8 と同じく分ける。終わっていなければ、待つためにポーリングせず、終わっていないことを完了報告に書く。
- PR のマージはユーザーの指示を待つ。
- 追跡する文書のバックログは、マージのたびには更新しない。0 の再開か 6 で終えるときに、マージ済みの項目をまとめて完了にし、`check` で集約の行を合わせてから 1 コミットにする（基準ブランチが保護されていれば 1 つの PR にする）。
  push と PR の作成は、0 の開始時に得た承認の範囲で行う。

## 6. 終える

- まとめて回す検証の前に fetch して、リモートの基準ブランチを fast-forward で取り込む。
- PR で取り込んだ項目が追跡する文書のバックログにあれば、上の「4. 受け入れる」のとおり状態をまとめて更新する。
