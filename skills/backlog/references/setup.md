# 置き場所を決める

宣言がないとき、置き場所を作るとき、宣言を書き直すときに読む。
置き場所の表は `SKILL.md` の「置き場所」節にある。

## 勧める順

表は勧める順に並べてあり、向いている場面に当たるもののうち上にあるものを勧める。
どれに当たるか分からなければ、追跡する文書を勧める。
issue を先頭にするのは、PR に紐づけた issue がマージで閉じ（PR の base が既定ブランチの場合）、ほかの置き場所と二重に持たずに済むため。
追跡する文書を追跡しないファイルより先にするのは、別の worktree からも読め、状態の更新が履歴とレビューに残るため。
メモリを追跡しないファイルより後にするのは、ほかのエージェントから読めないため（Claude Code のメモリは Codex や Gemini から読めない）。

## 宣言の書き方

宣言は、repo の指示ファイル（`AGENTS.md`、`CLAUDE.md` など。どれもなければ `AGENTS.md` を作る）の「バックログ」節に書く。
宣言には、置き場所と、計画のファイルかディレクトリ（メモリならその名前）を書く。
repo が種別を足していれば、その `--kind` の値も書く。
follow-up 用に別の名前の種別（`--kind=follow-up` や、以前の既定の後回しなど）を使っていた repo は、その項目の種別を改善候補に変え、宣言から外す。
GitHub の issue なら、`github-issues.md` の「宣言に書くこと」に挙げた項目も宣言に書く。

```markdown
## バックログ

repo で追跡する文書 `docs/plans/` に置く（`backlog` skill の書式）。
```

メモリに置く場合は、そのメモリの索引から引ける名前にする。

## 宣言がないとき

次の順に探す。

1. 表のヘッダを持つファイル：

   ```sh
   rg -l --hidden --no-ignore -g '*.md' -g '!.git' -g '!node_modules' -g '!.agents/lanes' '^\| # \| 状態 \| 種別 \| 依存 \|'
   ```

   追跡しないファイルも探すため、ignore を外す。
   `.agents/lanes/` は `parallel-lanes` が実行ごとに置く記録（バックログがないときは表を含む）なので除く。
   同 skill の宣言で別のディレクトリにしていれば、そちらを除く。
2. 散文のバックログ：`TODO.md`、`ROADMAP.md`、`docs/` や `plans/` の下の計画など
3. エージェントのメモリの索引
4. GitHub の issue：`gh` が使え、repo で issue が使われている場合

repo の中に置いた別の worktree（`git worktree list` に出る、メインの worktree 以外のパス）で見つかったものは同じ計画の写しなので除く。
見つけたものをすべて挙げてユーザーに確かめ、認められたら上の形で宣言する（次のセッションで探し直さないため）。
何もなければ下の「整える」に進む。

## 整える

置き場所がまだないときは、次の順に進める。

1. 置き場所の表の候補を、向いている場面と勧める 1 つとともに示し、ユーザーに選んでもらう。
2. 最初の項目をアプリの概要や要件から起こすときは、項目の案（ID、種別、依存、内容）を表の形でユーザーに見せ、確認を得る。
   まだ決まっていない前提（データの形式、方式の選択など）は判断の項目にし、それを使う実装の項目の依存に入れる。
3. 選ばれた置き場所を「宣言の書き方」の例の形で宣言し、計画を書いて `check` が通ることを確かめる。
   追跡する文書なら、計画は `docs/plans/<主題>.md` を既定にし、冒頭に見出しと概要を置いてよい。

散文で書かれたバックログ（箇条書きの TODO など）を表に移すときは、1 項目を 1 行にし、依存を ID で書き直す。
書き換える前に、移した結果を元の内容と並べてユーザーに見せる。
項目の順序は、散文での優先順位をそのまま表の順に写す。

## CI で `check` を走らせる

CI や pre-commit で `check` を走らせる repo は、dotfiles のない環境でも動かすため、`scripts/` を repo にコピーする。

- `plans.ts` だけでなく `package.json` もコピーする（`plans.ts` だけでは CommonJS の repo で動かない）。
- コピー元の dotfiles のコミットを冒頭のコメントに書く。
