# 状態の変更と follow-up の記録

項目を保留か取りやめにするとき、保留から戻すとき、判断の項目を完了にするとき、ユーザーの言葉で項目を止めるとき、follow-up や重い問題を足すときに読む。
各節は `SKILL.md` の「足す、更新する」節の項目を詳しくしたもの。

## ユーザーの言葉を読み替える

項目を止める言葉は、次のように状態に読み替える（集約の項目は除き、子の状態を変える）。

- 「保留」「あとで」「今はいい」「困ったら」など、今は手を付けないという言葉は保留にする。
- 「後回し」も保留にする。あとでやる含みがあるので取りやめとは読まない。種別も改善候補に変えない（理由は `SKILL.md` の「種別」の改善候補の項）。
- 「取りやめ」「やらない」「要らない」「不要」など、やらないと決めた言葉は取りやめにする。
  判断の項目では、その言葉を「やらない」の結論とみなして完了にする。ユーザーが「取りやめ」と明示したときだけ取りやめにする。
- 「見送り」は保留とも取りやめとも読めるので、どちらにするかをユーザーに確かめる。確かめるまで状態は変えない。
- 取りやめや完了にする項目に後ろの項目があれば、下の「後ろの項目の扱いを確かめる」に従う。

## 理由を残す

次のときは、`### <ID>` の節に日付と理由（判断の項目なら結論）を書く。

- 保留か取りやめにするとき（集約の項目は除く）
- 判断の項目を完了にするとき

表の状態だけでは、止めた理由も判断の結論も読めないためである。
保留にするときは再開の条件も書く（`status` で戻すかを決める材料になる）。決まらなければ未定と書いて完了報告で確かめ、決まったら同じ節に足す。
未着手に戻すときは、同じ節に再開の日付を足す。
GitHub の issue では、節の代わりに `github-issues.md` の「書き込む」に従う。

## 後ろの項目を見直す

次のときは、後ろの項目（依存している未着手、進行中、保留の項目）を取りやめにするか、依存から外す。

- 取りやめにするとき（その場で行う）
- 判断の項目を「やらない」の結論で完了にするとき（その結論で要らなくなった後ろの項目に限る）。
  前の項目の完了で依存が満たされるので、後ろの項目を残すと `ready` に出て自律の作業の対象になる。

## 後ろの項目の扱いを確かめる

後ろの項目を取りやめにするか依存から外すかは項目の範囲を変えるので、ユーザーに確かめる。

- ユーザーの言葉がその項目の扱いまで一通りに決めていれば（「オフライン編集はやらない」という言葉に対する「オフライン編集を実装する」の項目など）、確かめたことにし、変えた項目を完了報告に挙げる。
- 確かめたら、前の項目と後ろの項目を同じ更新で変える。
- 確かめられない間は前の項目も変えず、結論を前の項目の `### <ID>` 節に書き、確かめることを完了報告に書く。

## follow-up を残す

レビューの non-blocking な指摘など、後回しにした作業は、新しい項目として足すか、既存の項目の `### <ID>` 節に追記する。

- 新しい項目は種別を改善候補にし（実装にすると、ユーザーが選ぶ前に `ready` に出て自律の作業の対象になる）、内容を「〜を直す」「〜を足す」のように加える変更の形で書く。
  issue のバックログで改善候補に写すラベルを宣言していなければ、`github-issues.md` の「書き込む」に従う。
- 新しい項目の `### <ID>` 節には、次を書く。
  - 場面（誰が、どの環境で、どのくらいの頻度で遭遇するか）と手間の目安を 1 行ずつ（ユーザーが条件でまとめて選ぶ材料になる）
    利用者が遭遇しない指摘（テストの不足など）では、直さないと気づけなくなる不具合や退行を場面に書く。
  - 指摘の出どころ（どの項目のレビューか）
- 依存には、直す前に終えておく未完了の項目（同じ箇所を変更する実装など）だけを挙げ、関係があるだけの項目は節に書く（依存にすると `ready` に出なくなる）。
- 未着手か進行中の実装の項目の節には追記しない（その項目と一緒に、ユーザーが選ぶ前に自律の作業の対象になるため）。
- ユーザーが着手すると決めたら、種別を実装に変える。

## 重い問題を知らせる

作業の範囲外で見つけた問題のうち、データの消失や破損、セキュリティ、主要な場面で使えなくなるものは、判断の項目として足し、完了報告の先頭に書く。
`### <ID>` の節には、どの作業で気づいたか、場面（何をすると何が起きるか）、決めること（直すか、いつ直すかなど）を書く。
依存は `—` にし、同じ箇所を変更する項目などの関係は節に書く。ほかの項目の依存にこの項目を足すかは、結論が出てから決める。
種別を改善候補にしない（改善候補の項目に混ぜると、ほかの細かい項目に埋もれるため）。
